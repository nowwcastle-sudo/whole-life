# Whole Life

*[English](README.md) · 한국어*

Whole Life는 Windows를 우선 대상으로 하는 **로컬 오케스트레이션 계층**을 규격으로 정의한다. 여러 Claude Code 참여자와 Codex CLI 참여자의 협업을, **운영자 본인의 공식 CLI 로그인 하나로, 운영자 본인의 기기에서** 굴린다. 이것은 **1인용 도구다** — 로그인을 사람들 사이에서 중계하거나, 공유하거나, 한데 모으지 않는다.

> **상태:** 아키텍처 승인됨. 문서만 있는 단계다. 아직 동작하는 broker는 없다.

v0 설계는 공급자 집합을 의도적으로 작게 — Claude와 Codex 둘로 — 유지하면서, 한 협업 세션에 2~8명의 **1급 참여자**가 들어갈 수 있게 한다. 활동 중인 참여자는 각 공급자의 네이티브 서브에이전트에게 **범위가 제한된 읽기 전용 작업**을 위임할 수 있다. 일정 관리·상태·산출물 쓰기는 **단일 로컬 broker**가 독점한다.

## 시작하기

**아직 설치할 것이 없다.** 이 저장소는 승인된 설계를 담고 있을 뿐, 구현체가 아니다.

**설계를 읽으려면** [v0 명세](docs/spec/whole-life-v0.md)부터 보고, 그 결정의 근거인 [ADR 0001](docs/adr/0001-local-subscription-v0.md)을 이어서 본다. 승인된 베이스라인·고정 문서별 SHA-256 해시·공개 배포 관문의 항목별 현황은 [`docs/project-context.md`](docs/project-context.md)에 있다. [`CONTEXT.md`](CONTEXT.md)는 **도메인 용어집**으로, 명세가 규범적으로 쓰는 어휘를 담는다.

**v0가 나오면** 의도하는 모습은 이렇다 — **로컬 명령 하나**로 자기 PC에서 broker를 띄운다. Claude Code와 Codex CLI 로그인은 **지금 하시던 그대로 본인이** 한다. broker는 이미 설치돼 있는 CLI를 실행하고 그 출력 스트림을 읽는다. **구독 자격증명을 실행 경로 밖에 두는 것은 매 기동마다 검사하는 설계 요구사항이지, CLI가 영구히 보장하는 성질이 아니다** — [v0 경계](#v0-경계)를 볼 것.

**broker 자체는** 네트워크를 쓰지 않는다 — 공급자 API를 호출하지도, 서비스를 열지도, 다른 기기에 닿지도 않는다. 다만 broker가 실행하는 CLI들은 클라우드 기반이라 각자의 공급자와 **통신한다** — 손으로 직접 실행할 때와 똑같이. 경계는 「broker가 원격 표면을 더하지 않는다」이지 「세션이 오프라인이다」가 아니다.

## 기술 스택

| 계층 | 선택 |
|---|---|
| 런타임 | 로컬 Python 프로세스 하나 (`whole_life` 패키지). Windows 우선, macOS·Linux는 v0 이후 |
| 동시성 | `asyncio`. 하위 프로세스는 `shell=False` + 분리된 argv로만 띄운다 |
| 상태 | SQLite. **쓰기 연결은 하나뿐**이고, 추가 전용 이벤트 저널에서 재생한다 |
| 공급자 | Claude Code CLI(`stream-json`)와 Codex CLI(`JSONL`). 각각 런타임 어댑터 뒤에 둔다 |
| 프롬프트 전달 | **UTF-8 stdin**. 명령줄 인자로 넘기지 않는다 |
| 의존성 | 기본은 Python 표준 라이브러리. 그 밖의 것은 **측정된 요구사항과 ADR**이 있어야 한다 |

지원 CLI 버전은 **코드에 박힌 허용목록**으로 고정한다. 목록에 없는 버전은 「플래그와 스트림 형식이 그대로겠지」라고 넘겨짚지 않고 `UnsupportedCliVersion`으로 **기동을 거부한다.**

## 이 프로젝트가 존재하는 이유

지금의 에이전트 도구들은 이벤트를 스트리밍하고, 세션을 재개하고, 서브에이전트를 부를 수 있다. 다만 **공급자를 가로지르는 공유 협업 상태** — 일관된 재생(replay), 프로세스 정리, 컨텍스트 경계, 결정론적 출력까지 함께 제공하는 것 — 은 **저희가 아는 한 없다.** Whole Life는 그 로컬 제어 계층을 규격으로 정의한다.

## v0 경계

- Windows 위의 **로컬 Python 프로세스 하나**
- 런타임 어댑터 **둘** — Claude Code, Codex CLI
- **쓰기 주체가 하나뿐인** SQLite
- 에이전트 런타임은 **읽기 전용**. 산출물 커밋은 **broker만**
- 이벤트는 실시간 관측. AI 사이의 컨텍스트 교환은 **턴 경계에서만**
- 원래 답변·비평·합의·충돌·출처를 모두 보존하는 **결정론적 dossier**
- v0에는 **없다** — 웹 UI, 원격 서비스, 다중 사용자 자격증명 중계, worktree 쓰기
- broker 실행 경로에 **공급자 API 키가 없다** — 단, **현재 CLI 동작에 의존하는 조건부 성질이지 영구적 속성이 아니다.** Claude Code의 `--bare` 모드는 인증을 `ANTHROPIC_API_KEY` 또는 `apiKeyHelper`에서만 읽고 OAuth·키체인은 읽지 않으며, Anthropic은 `--bare`가 향후 릴리스에서 `-p`의 기본값이 된다고 문서화하고 있다. 그래서 broker는 CLI 버전을 고정하고, bare 모드가 꺼져 있음을 단언하며, 조용히 API 키로 갈아타는 대신 **실패로 닫는다**([명세 §5](docs/spec/whole-life-v0.md) 참조)

## 토큰을 의식한 협업

Whole Life는 **실제로 통제할 수 있는 것만** 제한한다 — 참여자 턴, 네이티브 워커 기동, 결과 바이트, capsule 바이트, projection 팬아웃. 토큰 수로 구독 쿼터나 과금을 예측하는 척하지 않는다.

| 프로파일 | 초기 참여자 | 증원 | 에이전트 간 교환 |
|---|---:|---|---|
| `economy` | 씨앗 2 | 없음 | 제한된 capsule |
| `balanced` | 씨앗 2 | 구조화된 검토가 충돌이나 근거 공백을 신호하면 **순서가 정해진 대기자 최대 2명** | 제한된 capsule |
| `deep` | 전원 | 없음 | 결정론적 순환 팬아웃. 전체 답변을 그물처럼 뿌리지 않음 |

전체 답변은 dossier에 남고, **다른 참여자의 프롬프트에는 절대 주입되지 않는다.** 공급자 경계를 넘는 것은 스키마 검증을 통과한 `handoff_capsule` 객체뿐이다.

## 보안과 정책 경계

Whole Life는 Claude나 ChatGPT의 **자격증명을 읽거나, 복사하거나, 내보내거나, 중계해서는 안 된다.** 인증은 공식 CLI 프로세스가 스스로 한다. 알 수 없는 인증, 알 수 없는 CLI 버전, 워커 관측 불가, 프로세스 결과 불명 — 이런 경우는 전부 **실패로 닫는다**(fail closed).

**기술적으로 가능하다는 것과 공급자 정책상 허용된다는 것은 다른 문제다.** 공개 배포 관문과 항목별 현황 — 이 저장소의 **공개 이력**을 포함해 — 은 [`docs/project-context.md`](docs/project-context.md)에서 추적한다. **구독 사용량 귀속은 아직 측정된 바 없으므로**, 이 저장소의 어떤 내용도 공급자가 이 사용을 어떻게 계량하거나 과금할지에 대한 진술로 읽어서는 안 된다.

## 이 저장소의 개발 방식

작업은 **8명으로 고정된 AI 에이전트 팀**이 전용 프로젝트 채널에서 수행한다. **11단계 흐름**을 따르며 단계마다 통과 게이트가 있다. 이미 있는 파일은 **확장하되 교체하지 않고**, `git push`는 **사람을 한 번 거친다.**

[`AGENTS.md`](AGENTS.md)는 이 저장소의 이슈트래커와 도메인 문서가 어디 있는지를 에이전트에게 알려주고, 상세는 [`docs/agents/`](docs/agents/)에 있다. 무엇이 이미 확립됐고, 무엇이 일부러 없으며, 에이전트가 이 저장소에서 어떻게 행동해야 하는지 — 전체 규약은 [CONTRIBUTING.ko.md](CONTRIBUTING.ko.md)에 있다.

## 개발 순서

구현은 이 문서 베이스라인 **이후에만** 시작한다. 첫 수직 슬라이스는 다음 셋이다.

1. 안전한 Claude·Codex 런타임 어댑터
2. 쓰기 주체가 하나인 SQLite 저널과 재생
3. 결정론적 dossier 내보내기

각 슬라이스는 **실패를 재현하는 테스트로 시작**해야 하고, 그 슬라이스의 **안전 불변식에 대한 변이 검사**를 포함해야 한다.
