제 00 편 · 원점편 · 초안

왜 시작했나

이 폴더의 서문이자, 이후 모든 편이 방향을 재는 자입니다.

2026-08-24 작성 · ORD-EDU-origin-premise-check · 대표 승인 대기

이 편의 용도

「지금 방향이 엇나가지 않았나」를 재려면 잴 자가 있어야 합니다. 이 편이 그 자이고, 이후 모든 편의 질문 11(원점에 비춰 그쪽으로 갔나)과 질문 12(처음 범위에서 새로 늘어난 것이 있나)가 여기에 대봅니다.

번호는 00이지만 시간상 첫 기록은 아닙니다. 나중에 쓰고 앞에 싣습니다. 승인 뒤에는 고치지 않습니다 — 고쳐야 할 만큼 문제 정의가 바뀌었다면 그 자체가 대표께 올릴 사건입니다.

무엇이 없어서

문제 — 도구는 다 있는데, 그것들 사이가 비어 있다

이벤트를 흘려보내고, 세션을 이어 붙이고, 새끼 작업자를 부리는 도구는 이미 여럿 있습니다. 없는 것은 그 도구들 사이입니다 — 서로 다른 회사의 AI 둘이 같은 상태를 공유하며 협업하고, 그 협업이 다시 재생되고 남는 자리.

「Current agent tools can stream events, resume sessions, and invoke subagents. We are not aware of one that also provides a shared cross-provider collaboration state with consistent replay, process cleanup, context boundaries, and deterministic output.」[1]

구체적인 아픔은 셋입니다. 전부 저장소가 스스로 적어 둔 것입니다.

  1. 협업 상태가 어디에도 없다 ADR — 「현재 검증할 문제는 서로 다른 두 공식 CLI의 context·event 협업이고」. API도 remote 표준도 이 문제를 푸는 데 필요하지 않다고 못박았습니다.[3]
  2. 합치면 반대 의견이 조용히 사라진다 ADR — 「합성은 반대 의견과 근거를 조용히 없앨 수 있다」. 그래서 세 번째 AI가 최종답을 만들지 않고, 원문·합의·충돌·출처를 고정 순서로 보존합니다.[4]
  3. 에이전트를 늘리면 사용량이 곱해져 터진다 ADR — 「agent 수·round 수·native worker 수·상호 원문 길이는 서로 곱해져 사용량을 폭증시킨다」. 그래서 원문 전체가 아니라 크기가 제한된 capsule만 오갑니다.[5]

누가 · 언제

매일 쓰는 물건이 아닙니다
「Someone who already uses Claude Code and Codex CLI separately and holds a subscription to each. They reach for Whole Life when a piece of work is long enough that they judge it needs several agents collaborating - not daily, but for a long sitting once opened.」[6]

쓰는 사람은 이미 두 CLI를 각각 쓰고 있고 양쪽 구독을 다 가진 한 사람입니다. 그래서 여러 사람의 로그인을 중계하지 않습니다 — 「단 한 사람의 도구이며 로그인을 사람 사이에 넘기거나 모으거나 공유하지 않는다」가 첫 문단에 박혀 있습니다.[7]

무엇이 성공인가 — 한 문장으로 적혀 있습니다.

「Success is that the operator can see what is happening — and above all, see the collaboration itself.」[8]

범위 밖

무엇을 안 하기로 했나

자의 눈금은 여기입니다. 질문 12(범위가 늘었나)는 이 목록에 걸리는가로 잽니다.

스펙 §2 「v0 비목표」 14개 항목 그대로입니다.[9]

  • 여러 사용자의 계정·구독 credential을 중계하는 서비스
  • mid-turn context push, running session attach, checkpoint, approval callback
  • AI가 파일을 직접 수정하는 worktree 협업
  • native worker를 독립 participant로 승격하거나 플랫폼 간 직접 연결하는 기능
  • recursive delegation(depth 2 이상)
  • Claude experimental agent teams와 그 shared task list·peer messaging
  • native tool 실행을 broker가 사전 승인했다는 보장
  • remote agent, multi-node, multi-process writer, web UI
  • A2A, MCP orchestration, AG-UI, CloudEvents SDK
  • FastAPI, Redis, NATS, Kafka, transactional outbox, CRDT, lease/fencing
  • ULID와 동적 plugin/adapter registry
  • AI가 최종답을 다시 합성하는 별도 judge turn
  • provider 구독 quota나 청구액을 토큰 수만으로 정확히 예측·우회하는 기능
  • unrelated task 사이에서 native session history를 재사용해 context를 무한 누적하는 기능

구조를 늘리는 것도 범위 밖입니다.

「Add a seam only after a second real implementation or process makes the existing concrete module leak complexity to callers.」[10] — 쓸모가 생기기 전에 자리를 만들지 않는다는 뜻입니다. 깊게 만들 모듈은 넷으로 못박혀 있고, 나머지는 「삭제해도 복잡성이 호출자에게 재등장하지 않는 가상 seam」이라 버렸습니다.[11]

자를 쓰는 법

「늘었다」와 「원래 그러기로 했다」를 가르는 것

범위 밖 목록만 있으면 「늘었다」는 판정은 되는데 「그럼 어떻게 하나」가 안 나옵니다. ADR 0001은 버린 것마다 「뒤집는 조건」을 함께 적어 두었습니다. 범위 밖의 것이 필요해 보일 때 물어야 할 것은 「하면 안 되나」가 아니라 「그 조건이 왔는가」입니다.

맨 아래 줄은 왜 그렇게까지 조심하는지도 한 문장으로 적어 두었습니다 — 「기술적 subprocess 실행 가능성과 provider 정책상 공개 제품 허용은 다른 명제이고, push·공개는 되돌리기 비용이 크다.」[14]

빈 칸

자료로 채울 수 없는 것 하나
대표만 채울 수 있는 칸

저장소 문서는 「무엇이 없어서 만드나」를 충분히 적어 두었습니다. 적혀 있지 않은 것은 「어느 순간에 이게 필요하다고 느꼈나」 하나입니다 — 대표가 실제로 두 CLI를 따로 돌리다 막혔던 그 장면.

이것은 비워 둡니다. 없다고 자가 못 쓰이는 것은 아닙니다 — 방향을 재는 데는 위의 「문제」와 「범위 밖」이면 충분합니다. 대표께서 한 문장 주시면 여기에 넣겠습니다. 추측해서 채우지 않습니다.

이 편의 상태

초안입니다

이 편은 기획자를 부르지 않고 저장소 문서만으로 썼습니다. 통치자가 「기획자를 부르기 전에 전제부터 확인하라」고 물었고, 확인 결과 「문제」와 「범위 밖」 두 칸이 이미 차 있었기 때문입니다. 다만 「문제」는 스펙 §2에 있지 않습니다 — §2 「목표」는 무엇을 만드나를 적은 해법 서술이고, 왜 필요한가는 README.md의 「Why this project exists」와 PRODUCT.md, 그리고 ADR 0001의 「왜」 항목들에 있습니다.

승인 뒤에는 고치지 않습니다. 새 결정을 담지 않았고, 스펙·ADR 파일은 건드리지 않았습니다 (승인 기준선이라 해시 행이 걸려 있습니다). 이 편은 기존 문서를 옮겨 엮은 것일 뿐 새로 정한 것이 없습니다.
