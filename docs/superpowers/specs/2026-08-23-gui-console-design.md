# Whole Life GUI — 콘솔 표면 설계

작성 2026-08-23 · 대상 표면 하나(콘솔) · impeccable mode `Operate`

## 1. 이 문서의 지위

**확정된 설계이고, 구현 지시가 아니다.** 구현은 아래 순서의 세 번째다.

1. v0 브로커 CLI 완성
2. **v1 사양 확립** — 실시간 협업 모델을 전체 엔지니어링 과정으로 다시 세운다
3. GUI 구현 착수

이 문서는 **v1이 무엇이 되든 변하지 않는 것**만 확정한다. v1에 종속되는 것(진행 표의 열 구성·갱신 주기·충돌 표시 방식)은 **영역만 확보하고 비워 둔다.**

제품 진실은 `PRODUCT.md`가 소유한다. 이 문서는 그것을 복사하지 않고 참조한다.
`DESIGN.md`는 **여기서 쓰지 않는다** — impeccable 규칙상 지어진 세계에서 완성 시점에 쓴다.

## 4. 색 · 어둠 · 서체

**색 전략: Full palette(역할 3~4개).** Operate의 기본값은 Restrained지만 여기서는 색이 장식이 아니라 기능이다 — participant를 구별하고 상태를 구별해야 한다.

**어두운 지면.** 습관이 아니라 장면이 강제했다: *혼자, 자기 방 PC 앞에서, 긴 작업 하나를 걸어 두고 오래 지켜본다.*

**팔레트 출처는 gruvbox** — 운영자가 못 박은 구속이다. 색값은 **구현 전에 공식 출처에서 대조한다.** 이 문서는 색값을 확정하지 않는다.

**피해야 할 클러스터**: `near-black + 네온 액센트 + 발광 테두리`. gruvbox dark는 방심하면 그리로 미끄러진다. 갈림길은 **발광 여부**다 — gruvbox의 색은 형광이 아니라 눅은 흙빛이고, **무광 패널로 가면 벗어난다.** 빛나는 테두리를 쓰지 않는다.

**서체**: 본문·라벨은 시스템 스택. 숫자는 tabular numerals — **「개발자 도구니까 모노」가 아니라 「표가 흔들리면 못 읽으니까」다.** 디스플레이 서체는 구현 시점에 impeccable의 금지 목록 밖에서 고른다.

## 5. 첫 뷰포트

```
+--------+--------------------------------------------------+
|패치베이| SESSION . Turn 3 . Round 2 . 00:41:12   [기록열기]|
|        | ~ 지나간 Turn의 자국 ~~~~~~~~~~~~~~~~~~~~~~~~~>  |
| 회계정리|--------------------------------+-----------------|
| 사양감사| PARTICIPANT                    | ROSTER          |
| >청춘케어| +-----++-----++-----++-----+   | PROFILE         |
| 스킬개편| |strip||strip||strip||strip|   |                 |
|        | +-----++-----++-----++-----+   | [정지]          |
|  ----  |--------------------------------+-----------------|
| [전원][사용자][설정] | TASK - 다음 지시          [보내기]  |
+--------+--------------------------------------------------+
   16%                  ~62%                      22%
```

**한 문장으로**: 좌는 어떤 세션인가, 상은 어디까지 왔나, 우는 어떻게 운영하나, 하는 다음에 무엇을 시킬까. **이 넷은 상시고 중앙만 전환된다**(콘솔 ↔ 기록).

### 영역별 규정

**패치베이(좌 16%)** — 믹싱 콘솔의 패치베이다. SaaS 내비게이션이 아니다.
- 다른 세션들의 목록. 항목은 **카드가 아니라 한 줄 라벨 + 상태 램프**
- 이름은 `세션 1`이 아니라 **그 세션 Task의 첫 줄**
- 발치에 전원 램프(Preflight) · 사용자 · 설정
- **접히지 않는다.** 아이콘 레일로 축소되지 않는다

**상단 시간축(가로)** — 이번 세션의 시간. 현재 위치와 지나간 Turn의 자국. 오른쪽 끝에 기록 열기.

**PARTICIPANT(중앙 ~62%)** — 화면의 주인공. **여기가 지면을 지배하지 않으면 그 자체로 실패다** — 성공 정의가 「협업이 잘 보이는 것」이기 때문이다. 스트립 하나에 라벨·상태·활동·토큰·이번 Turn 요약. 그 아래 Native worker 활동.

**ROSTER / PROFILE(우 22%)** — 이 세션을 어떻게 운영하나. 주 동작(시작·정지)이 여기 있다. 구석이 아니라 **그것이 바꾸는 것 바로 옆**이다.

**TASK(하)** — 항상 있다. 크기가 변하지 않는다. 중장기 작업은 지시 한 번으로 끝나지 않으므로 **물러나면 안 된다.**

### 상태 전이

- **첫 실행**: 패치베이가 40%까지 넓어지며 전원 진단이 펼쳐진다. 세션 목록이 비어 있으니 「이 콘솔에 물린 것은 전원 문제뿐」이 크기로 말해진다. 실패 코드(`UnsupportedCliVersion` 등)를 사람 말로 번역하고 **붙여넣을 명령을 복사 버튼과 함께** 준다. 설치는 대행하지 않는다.
- **통과 후**: 패치베이가 16%로 접히고 콘솔에 전원이 들어온다. 되돌릴 때는 같은 경로를 역으로 간다.
- **기록 열기**: 중앙만 덮는 층이 올라온다. 패치베이·시간축·TASK는 남는다. 누른 자국에서 앵커되어 올라오고 같은 경로로 내려간다.

### 기록 층

사양 §11의 **8개 섹션과 순서를 그대로** 렌더한다. 순서를 재배열하지 않는다. 좌측에 섹션 색인.

세션이 닫히기 전에는 **확정 전 투영**이다 — 배지로 `확정 전 · Turn n까지`를 명시한다. **확정본과 진행본을 혼동하지 않는 것이 이 제품의 약속에 직결된다.**

6번 「미해결 충돌」에 **교차 해칭**을 쓴다. 색만으로 충돌을 표시하지 않는다.

## 6. 모션 문법

| 대상 | 값 |
|---|---|
| 버튼 | pointer-down에 **즉시** 반응. `scale .97 / 100ms`. 릴리스를 기다리지 않는다 |
| 패널 접힘·펼침 | 스프링 `damping 1.0 / response 0.4`. 오버슈트 없음 |
| 모달·팝업 | `transform-origin`을 **띄운 요소에 앵커**. 화면 중앙에서 튀어나오지 않는다 |
| 값 변경 | **자리를 옮기지 않고 그 자리에서 전이** |
| 던진 동작 | 그때만 `damping ~0.8`. 그냥 나타나는 패널에 오버슈트를 주지 않는다 |
| 감속 접근성 | `prefers-reduced-motion`에서 이동을 크로스페이드로 대체하고 오버슈트를 제거 |

모든 애니메이션은 **중단·역전 가능**해야 하고 **현재 화면값에서** 시작한다.

## 7. 재질

무광 패널이 기본. 반투명(`backdrop-filter`)은 **모달 오버레이에만** 절제해서. 상시 표면에 깔지 않는다. **빛나는 테두리를 쓰지 않는다.**

## 9. 이 표면이 브로커 CLI에 요구하는 것

GUI는 CLI의 껍데기다(운영자 결정). 따라서 **CLI 표면이 GUI 능력의 상한**이다. 아래는 이 설계가 성립하기 위해 브로커 CLI가 제공해야 하는 것이고, **v0 CLI 구현이 참조할 요구사항**이다. 사양은 브로커 자신의 명령 표면을 규정하지 않으므로 이는 사양 개정이 아니다.

- **Preflight 조회** — 두 CLI의 감지·인증·버전 판정을 기계 판독 가능한 형식으로. 실패 시 판정 코드와 **사람이 읽을 수 있는 진단**을 함께.
- **세션 목록·열기·생성** — 목록 항목에 이름(Task 첫 줄)·상태·마지막 시각.
- **세션 시작** — roster와 profile을 인자로.
- **Turn 제출** — 지시 텍스트를 stdin UTF-8로. 명령행 인자로 넣지 않는다.
- **이벤트 구독** — `(session_id, session_seq)`에서 replay 가능한 스트림. 사양 §9의 fan-out 모델과 같은 계약.
- **취소** — 진행 중 Turn을 cancel하고 partial을 commit.
- **기록 조회** — §11 순서의 투영. 확정 여부를 함께.

**GUI는 브로커의 상태 저장소(Journal·SQLite)에 쓰지 않는다.** 단일 writer 불변식이 그 이유다. 읽기만 하고, 실행은 CLI를 자식 프로세스로 띄운다. 브로커에 service 표면을 만들지 않는다.

## 12. 구현 착수 시 지켜야 할 계약

impeccable 규칙이고 생략하면 계약 위반이다. 구현이 한참 뒤에, 다른 손으로 이뤄지므로 여기 적어 둔다.

- 코드를 쓰기 전에 **방향 계약**을 산출물의 첫 주석으로 박는다. 다섯 블록, 150단어 이내: THESIS(이 표면이 소유한 하나의 생각과 거부하는 기본 배치) · OWN-WORLD(내용을 다 지워도 알아볼 수 있는 팔레트와 컴포넌트 언어) · STORY(방문자가 이해하고 믿고 행하는 것) · FIRST VIEWPORT(무엇이 어디에 어떤 크기로, 주 동작은 어디) · FORM(고른 형식, 내 순위에서의 위치, seed key `63528f01`).
- 마지막 줄은 **FINISH**이고 문구를 그대로 쓴다: `unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance`
- **HTML 주석으로** 루트 레이아웃 body의 첫 자식에 둔다. 템플릿 프론트매터 주석만으로는 안 된다 — 빌드가 지운다.
- 첫 프로덕션 빌드 뒤 **빌드 산출물에서 seed key를 grep**한다. 빌드가 지운 계약은 아무도 감사할 수 없다.
- 이 환경에는 이미지 생성 도구가 없으므로 **code-led**다. comp 라운드는 계약상 생략이지 표류가 아니며, 야심은 FIRST VIEWPORT 블록과 명명된 시그니처 상호작용이 짊어진다.
- `DESIGN.md`는 **완성 시점에 지어진 세계에서** 쓴다. 미리 쓰면 현실을 기술하는 대신 방어하게 된다.
